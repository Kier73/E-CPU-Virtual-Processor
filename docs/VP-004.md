# VP-004 — Ground-first neural realization over one E-CPU observer-host

**Status: implemented integration candidate. Native MailCPU verification must finish in GitHub Actions before this can be called verified.** This change is stacked on the draft VP-003 branch. It does not turn VP-002/003 draft code into mainline.

## Hypothesis

Can existing E-CPU **Structural Memory**, **ContextualOrbitAddress**, **VerifiedGroundRealizer**, **HeadlessOS Hypervisor**, **VirtualLayerRuntime**, and **NavigableComputationDAG** connect one mathematical Ground query to **actual parameter-bearing neural inference**, without adding a second Ground authority, scheduler, or interpreter?

The operation has exactly two dependency nodes:

    Typed request / model Ground / local verified weight index
       |
       v
    E-CPU admitted token-position law, exact coordinate observation
       |   Hypervisor READ; observer and structural-memory receipts
       v
    Native E-CPU pure numerical operator
       |   Hypervisor COMPUTE; receiver-owned weights
       v
    Numerical verification, DAG commit, reconstruction, query receipt

The **same E-CPU HeadlessOS and Hypervisor** authorize both the Ground read and neural execution. The Ground observation is committed to an actual E-CPU DAG before the neural operation becomes ready. The native model handler requires a locally issued, request-bound observation and matching model/weight identity. It refuses attempts to bypass the predecessor by calling it with an invented receipt.

## What the Ground means

VP-004 first admits an **explicitly declared** integer Ground with `x(t) = t mod 2^63`, supported by synthetic finite witnesses. The coordinate is an E-CPU **logical token index**, not the result of tokenization or a learned sequence state. The model Ground binds the receiver's exact weight index and the layer number.

The neural input is an **externally supplied hidden activation**, not magically derived from the token index. It can later be replaced by the previous model layer's committed activation or by a source-pinned embedding output. The input digest and model/index identity are bound into the neural node of the DAG. A numerical output therefore proves one native **MoE feed-forward sublayer** has run, not a full Qwen3 token, attention operation, autoregressive continuation, or a physically passive path transformation.

There is no 30B/235B cap on the query's semantic shape. A full pretrained model still requires access to its exact weights, compatible numerical operators and enough real execution/storage capacity for the *requested* observation. This adapter loads only selected experts.

## Run

Requires a source checkout with native MailCPU importable and a provisioned VP-003 sparse weight index. To demonstrate the **actual two-stage E-CPU path** with clearly labeled synthetic weights:

```sh
python -m pip install -e external/ecpu
python -m pip install numpy torch safetensors
python examples/provision_sparse_demo.py --output local-moe-demo
python -m vp.ground_neural \
  --index local-moe-demo/weights.json \
  --hidden local-moe-demo/hidden.json \
  --token-coordinate 1000000000013 \
  --request-id vp004-observe-neural > vp004-receipt.json
python -m unittest discover -s tests -p 'test_ground_neural.py' -v
```

This run constructs and admits a token-position Ground, navigates directly to the requested distant coordinate without enumerating intermediate positions, executes a real numerical sparse MoE sublayer through the native E-CPU Hypervisor, verifies its result, and reconstructs the completed DAG snapshot. The emitted receipt retains independent model, weight-index, Ground projection, observer receipt, operator contract, numerical result, and DAG identities.

For an already provisioned actual Qwen3 checkpoint, use VP-003's `vp.qwen_snapshot` to form its **receiver-owned** sparse tensor index and a genuine hidden activation from the appropriate preceding layer. The adapter itself does not download weights or substitute a synthetic model on failure.

### Negative tests

- Unadmitted model Ground, malformed activation, invalid token coordinate, or extra request fields → refused before execution.
- Missing Structural Memory READ capability → native inference not invoked.
- Missing COMPUTE capability → Ground observation may succeed, but neural node remains uncommitted and zero neural handlers execute.
- Repeated query ID with altered activation → refused. Exact duplicate returns its original verified query envelope.
- Forged or altered numerical output → independent recomputation from the resident weight source refuses it (in VP-003 numerical tests).
- Distant coordinate (10^12+) → no linear traversal of token-position law.

## Important continuity limits

The current prototype has a process-local query replay cache and in-memory E-CPU DAG snapshot. It **does not yet persist a multi-token KV cache or model session through an actual hard process kill**, nor demonstrate end-to-end full-model inference, independent hosted machines, or numerical execution at a passive communication-path locus. The native E-CPU operation ledger protects same-process pure operator replay, while the earlier VP-001 state branch demonstrates persistence for its **different affine Ground**. Joining these for resumable model inference requires checkpointed token/KV state and independent recovery authority, not just identical digest labels.

No false “universal executor” is introduced. The next transition is **native, dependency-bound embedding → RMSNorm → QKV/RoPE/GQA attention → MoE → output projection**, each using existing E-CPU operator and DAG contracts, and subsequently commit actual token/KV continuation across host replacement. VGI and IFS should independently verify the resulting composed Ground, not provide or override E-CPU authority.
