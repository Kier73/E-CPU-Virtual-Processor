# VP-001: a persistent, interactable E-CPU observer-host

**Status:** initial runnable implementation; hosted Actions execution must be observed before operational verification is claimed.

## Exact objective

Can the same logical computational identity be addressed before, during and after the complete termination of a realization host, while independently validating what was computed and what state transition was committed?

The first answer is deliberately finite and exact. A virtual processor admits a single mathematical Ground, `(a*x+c) mod m`. Its logical cursor is a coordinate in that Ground; observation is performed by E-CPU's exact native orbit navigation, not by a local emulation. The cursor and its evidence persist in a Git branch. The interface is a GitHub `workflow_dispatch` command, and a runner's lifetime is irrelevant to the retained cursor.

## Protocol

- **Identity**: `processor_id` in an immutable genesis record; the initial deployed identity is `ecpu-vp-primary`.
- **Ground**: immutable `affine-modular-v1`, with `a=1664525`, `c=1013904223`, `m=2^32`, `x0=73`. This is an admitted synthetic law, not a physically observed transition.
- **Coordinate**: nonnegative integer `t <= 2^63-1`. Time here is **logical coordinate** only; wallclock elapsed time is not inferred.
- **Realization**: `mailcpu.law_certifier.lcg_navigate(a,c,m,x0,t)` must equal `A*x0+B mod m` where `(A,B) = mailcpu.rrns.affine_orbit_jump(a,c,m,t)`. Refuse missing native E-CPU or disagreement.
- **Intention**: `observe`, `peek(target)`, `navigate(target)`, `advance(distance)`; caller supplies an immutable `request_id` and actor label. No arbitrary executable input. A `peek` does not move the persistent cursor.
- **Receipt**: exact canonical JSON, containing sequence, previous digest, processor ID, full intention, before/after cursor, observed coordinate/value, native realizer label and pinned upstream revision; SHA-256 covers all fields.
- **Recovery**: re-parse and independently reconstruct each record from genesis before accepting a new command. Reject missing, malformed, noncanonical, re-ordered, duplicated, hash-mutated, contradictory or out-of-domain records.
- **Idempotency**: exact request retry returns the already committed receipt; changed semantics for an existing ID are rejected. This is journal idempotency, not exactly-once execution of external effects.
- **Durability**: atomic write+fsync to a runner's staging file, then non-force Git push to `processor-state`. Only the successful remote push constitutes a completed persisted operation. Actions group concurrency serializes this processor within the repository. A competing non-fast-forward push fails closed.

## Reproducer

On a native E-CPU installation:

```sh
python -m vp.cli bootstrap --journal local-state/primary.jsonl
python -m vp.cli run --journal local-state/primary.jsonl --actor test --request-id first --operation navigate --coordinate 999999999999
python -m vp.cli verify --journal local-state/primary.jsonl
# Stop every Python process. Start a new interpreter.
python -m vp.cli run --journal local-state/primary.jsonl --actor test --request-id second --operation observe
python -m vp.cli verify --journal local-state/primary.jsonl
```

The GitHub Action uses the same protocol but restores the journal from a separate branch and commits it remotely. Its `GITHUB_TOKEN` requires `contents: write` and is only exposed in a manually triggered workflow on the default branch. No `pull_request_target` or issue-comment-triggered execution is enabled.

## Truth, trust and refusal

A digest proves byte consistency under an assumed trusted digest head; it is not a signature or unforgeable proof of a Git administrator's actions. The Git branch is one administrative and storage failure domain. It is **not** a quorum, Byzantine consistency protocol, neutral arbitrator, or indefinite free hosting provider. Runners may queue or fail, and GitHub administrators may disable Actions or force-rewrite the state branch.

The `actor` string records the workflow-provided GitHub actor; the standalone CLI does not authenticate it. The GitHub Actions identity derives from the user authorized to invoke `workflow_dispatch` with repository workflow permissions, subject to repository settings. GitHub API approvals or protected-branch rules can still prevent the push. A failed push must not be reported as committed output.

`lcg_navigate` and `affine_orbit_jump` provide two independently written derivations of the *same stipulated Ground*. Agreement does not establish that the Ground describes a real-world causal process. No physical path-substrate compute, energy reduction or general VM emulation is claimed.

The current implementation revalidates history linearly on restore, bounded by an explicit local journal quota. It directly navigates the requested coordinate in O(log t) E-CPU arithmetic. Future checkpointing must preserve exact lineage and independent witnesses without confusing bounded local read cost with global navigation cost.

The external protocol stays stable while its realizer changes.

**VP-003 — reproducible virtual execution**: add hypervisor-gated HeadlessOS/Virtual Layer operator invocations, native input/output receipts, and explicit replay/effect classes. Continue to forbid arbitrary user-submitted code until an authorization and sandbox contract exists.

**VP-004 — independent authority and recovery**: adapt the existing `RecoveryLineageCoordinator`/mTLS authority service across independent durable failure domains. A Git branch can retain portable evidence but cannot impersonate protected majority state.

**VP-005 — continuous API and substrate migration**: present the same processor identity via a live authenticated endpoint, a GitHub Actions host, and external observer-hosts. Prove that host replacement, partition, or loss cannot silently change the Ground, accepted intention or committed result. Measure the difference between logical continuity, availability latency and physical-path realization.

The long-term target is to make computation addressable and verifiable across hosts and communication paths, instead of treating local iterations or processor possession as the fundamental computational identity.
