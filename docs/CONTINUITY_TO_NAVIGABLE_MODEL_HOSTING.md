## 2. What is reused here — no parallel E-CPU

The first step toward model-size-neutral execution is to define an **intention-scoped cut** through a valid, typed computational model. The observer requests one coordinate and one output projection; the Ground determines whether that output can be directly navigated, generated from a verified law, recovered from a committed observation, or needs an actual realization. All four outcomes remain distinguishable.

E-CPU already provides the appropriate existing components:

- **Navigational algebra:** `mailcpu.law_certifier.lcg_navigate` solves an affine recurrence at coordinate t in O(log t), rather than executing t transitions. Its full-period power-of-two LCG permits exact addressability across a huge expert-index space.
- **State authority and memory:** `ComputationalObjectStore` (M1 bytes), `ComputationalSessionStore` (M3 versioned CAS state), `RecoveryLineageCoordinator` (strict-majority high-water), `StructuralMemoryRegistry` (admitted scalar law families), and typed immutable Ground identities.
- **Execution authority and orchestration:** `VirtualLayerRuntime`, `HeadlessOS`, `Hypervisor`, `ComputationalNode`/`NavigableComputationDAG`, and independent observer receipts. Capabilities belong to receiver-owned identities; transport and caller descriptions do not grant them.
- **Communication-path mechanisms:** TCP/TLS, ReliableChannel, authenticated Transit, observer-host path qualification, and GitHub Actions as a disposable observer service with branch/artifact retention. A qualified channel may carry and store Ground state even when a particular realization locus disappears; evidence must show which component actually transformed the information.
- **Real-source parameter routes:** MWS-001/002 for exact and lawful generated bit patterns, HFR for pinned source metadata/header ranges, HFG for typed per-layer dependencies, and VP-003 for native sparse numerical operator/weight verification. The next integration should bind these instead of treating model identifiers as executable data.

## 3. VP-005's deliberately narrow new theorem and runnable use

A synthetic model Ground specifies N experts, with N a power of two, and defines one exact algebraic router score for expert index j:

`score(j, t) = -(j - lcg_navigate(5, 1, N, 7, t))**2`.

The top k experts are necessarily the k nearest integers to the center, with deterministic ascending-index ties. This is proved by monotonicity of squared distance on each side of the center; every discarded index lies outside the nearest-k interval and therefore cannot have a higher score. The selection has **O(k)** work and does not inspect N router entries. The selected experts' small integer-valued gated ReLU networks have all parameters exactly generated from an admitted procedural law and their outputs are recomputed by a separate scalar oracle.

For `N=2**48`, `hidden_dim=3`, `intermediate_dim=4`, `top_k=8`, the model denotes **10,133,099,161,583,104** logical parameter coordinates, but a query visits eight expert parameter groups. At `t=2**56+73` the native MailCPU law can navigate the center without replaying ~7.2e16 earlier positions. This is **logical structural scale**, not a claim of storing or training that many independent weights.

The published API is `vp.navigable_experts`, and the hosted pipeline is [vp005-navigable-experts.yml](../.github/workflows/vp005-navigable-experts.yml): `observer-plan` → GitHub artifact → `observer-receiver` (native E-CPU Hypervisor) → GitHub artifact → `independent-observer-verifier`. The receiver and verifier independently instantiate the pinned Ground from code rather than trusting a source identity supplied by the planner.

**What is not transplanted:** an ordinary Qwen/GPT router computes scores from actual matrix weights over its declared expert set; it is not equivalent to this nearest-center score. Only a proven translation and actual trained weight availability could replace that routing with a closed-form navigator. Fully general nonlinear neural computation has no known universal mechanism for avoiding all required data/operations.

## 4. Research ladder from architecture to usable large models

The next E-CPU development need is not a second distributed VM or another mock 235B manifest. It is a single **Ground-to-Observation interface** that records the complete model-source identity, coordinate, demanded operator cut, evidence class, selected realization method, host/path identity, authority decision, and independently verified output. For a real pretrained model the policy must choose between:

1. **Known exact Ground law or cached, verified observation:** directly navigate or recover the specific projection, with original model/source scope unchanged.
2. **Qualified generated or reused tensor bytes:** use MWS-001/002 from an independently trusted source; never invent unknown trained parameters from a hash or shape.
3. **Necessary numerical operation:** run only the required HFG/VP expert/layer cut under the native E-CPU Hypervisor, and preserve typed predecessor output, KV state and source/receipt hashes in the existing M3 quorum session.
4. **Unavailable Ground, source or authorized observer-host:** return an unresolved receipt rather than fabricate a model output.

**Near-term falsification:** run a real pinned Qwen multi-layer selected tensor cut with predecessor values derived from previous executed layer outputs, not externally supplied hidden vectors; commit state to M3, destroy the original observer process, restore through another authorized process/route and verify the next token against an independently implemented numerical reference. Couple this to real TCP/mTLS or a qualified GitHub artifact API transport without treating transport acknowledgments as semantic acceptance. A future qualified direct path-transform may replace an ordinary numerical operator *only if measured path observations establish the exact relation*.

The objective remains **a virtual model whose identity, state, memory and semantics survive every selected realization host**. That is different from claiming matter or physical activity cease to exist. No specific GPU, CPU model, vendor or enduring physical host belongs to the mathematical identity of the computation; qualified active observers and communication paths must still supply the observed effects required by its Ground.
