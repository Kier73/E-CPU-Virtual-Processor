# VP-003 — Queryable neural execution across model scales

**Status: runnable local implementation; GitHub-hosted integration verification pending.**

This milestone defines two actual neural inference surfaces, without confusing them:

1. **E-CPU-native, sparse numerical inference:** an E-CPU `VirtualLayerRuntime` / Hypervisor operator uses receiver-owned, verified parameter tensors to compute a SwiGLU MoE feed-forward sublayer. Router logits come from an actual router matrix multiply, not caller-supplied synthetic logits. Source can be `.npy` or `.safetensors`, including BF16. The operator computes an output and selected scalar coordinates are checked independently. This is **not yet a complete Transformer forward pass**, autoregressive generation, or 235B execution.
2. **Full-model text queries:** a locally provisioned `AutoModelForCausalLM` and `AutoTokenizer` can execute greedy autoregressive generation, under E-CPU's receiver-local Hypervisor and pure operator contract. The math here runs through a disclosed **Transformers/PyTorch realization**, not E-CPU's own SIMD/SIMT tensor backend. Model sizes are not hard-coded; admitted execution depends on actual memory, storage, accelerators, host topology, and model-family support.

Neither mode substitutes a mock model when an actual weight payload is missing. Partial or forged evidence is refused.

## Use it today: direct sparse neural inference

Requires Python 3.11+, E-CPU (same pinned revision as VP-001), NumPy, PyTorch, Safetensors:

```bash
python examples/provision_sparse_demo.py --output local-moe-demo
python -m vp.sparse_query \
    --index local-moe-demo/weights.json \
    --hidden local-moe-demo/hidden.json \
    --request-id first-neural-query
```

The example creates **explicitly synthetic** 128-expert parameter tensors, provisions only the eight experts selected by its deterministic real router multiplication, then invokes the actual `mailcpu.VirtualLayerRuntime` + Hypervisor. Its output receipt includes model Ground, index digest, selected experts, loaded tensor digests, output digest, scalar oracle coordinates, and operator-contract / Hypervisor decision evidence. It is a true numerical forward for a *single sparse expert sublayer*, not a pretrained LLM. No 235B tensor payload is synthesized or declared loaded.

A receiver may instead provide a trusted `weights.json` with real Safetensors files and an independently pinned `--expected-index-digest`. The index keys follow `experts/{id}/{gate|up|down}` plus `router`. Source paths must be local regular files; remote shards must first be provisioned through authenticated/object-verified E-CPU or equivalent storage. The manifest binds model Ground identity and full declared shapes; Qwen VP-002 Grounds receive additional strict shape checks.

### Use an actual Qwen3 local checkpoint (without materializing all experts)

With a locally provisioned official Qwen3-30B-A3B or Qwen3-235B-A22B snapshot, including `model.safetensors.index.json` and its referenced source shards, first calculate a real router decision for an actual hidden vector:

```bash
python -m vp.qwen_snapshot \
    --snapshot /models/qwen3 \
    --model qwen3-235b-a22b \
    --layer 0 \
    --hidden /models/query-hidden.json \
    --output /models/qwen3/vp003-layer-0.json \
    --expected-weight-map-sha256 <externally-pinned-source-index-sha256>

python -m vp.sparse_query \
    --index /models/qwen3/vp003-layer-0.json \
    --hidden /models/query-hidden.json \
    --request-id qwen3-layer0-query
```

The hidden vector must be a valid `hidden_size`-element observation from the **correct preceding layer**, not an invented prompt embedding. The adapter checks declared Qwen dimensions, reads the router payload, computes top-k from its real logits, resolves only the chosen eight experts' Safetensors tensor *headers*, verifies each distinct physical shard by SHA-256 and writes a typed local index. The native E-CPU operation subsequently reads the selected expert tensors and performs the numerical forward. This is **one sparse feed-forward sublayer**; a full prompt-to-text inference still needs the preceding attention layers, later layers, KV cache, and tokenizer. An externally pinned original Safetensors index and independently established snapshot provenance remain necessary for a stronger source-authenticity claim. It performs no network download and does not fabricate inaccessible shard data.

### E-CPU numerical operation

The first public operation implements, for one hidden vector `x`:

```text
logits = W_router @ x
chosen = deterministic_topk(logits, k)
weight = softmax(logits[chosen])
result = sum(weight[i] * W_down[i] @
             (silu(W_gate[i] @ x) * (W_up[i] @ x)))
```

It uses float64 NumPy accumulation and an independent Python `math.fsum` scalar calculation for sample output coordinates. Therefore it is **not guaranteed bitwise equivalent to a BF16/F16 accelerator Transformer runtime**; exact dtype, reduction order, fused kernels and tolerances require a separate comparison contract. Only selected expert files are materialized; the entire model does not have to reside on this worker. Hashing the selected physical shards and numerical arithmetic still consume actual CPU, memory and I/O resources. This is numerical computation on ordinary hardware, not proof of computation by a passive network link.

## Query a preprovisioned full language model

Requires the pinned E-CPU package, PyTorch, Transformers and Accelerate, and sufficient weights / computational resources:

```bash
python -m pip install torch transformers accelerate safetensors
python -m vp.query \
    --model-id Qwen/Qwen3-30B-A3B \
    --revision e187836637046dedaf8a1f27c91bf65c5175cc97 \
    --prompt "Describe a new computational Ground" \
    --request-id query-001 \
    --max-new-tokens 64
```

Default: offline model resolution (`local_files_only=True`), with no hidden download. Use `--allow-download` explicitly to permit acquisition from the model host, subject to published access terms and infrastructure capacity. The revision names the model configuration provenance; a production local checkpoint should additionally be admitted through content-addressed byte manifests and tensor hashes. This path **does execute full-model neural inference** when a supported model and its weights are present, but its numerical operations are **Transformers/PyTorch hosted**, governed by an E-CPU Virtual Layer operator.

For a warm local HTTP query interface:

```bash
export ECPU_VP_API_TOKEN='replace-with-a-long-random-token'
python -m vp.query_server --model-id Qwen/Qwen3-30B-A3B \
    --revision e187836637046dedaf8a1f27c91bf65c5175cc97 \
    --host 127.0.0.1 --port 8765
curl --silent http://127.0.0.1:8765/query \
    -H "Authorization: Bearer $ECPU_VP_API_TOKEN" \
    -H "Content-Type: application/json" \
    --data '{"request_id":"query-002","prompt":"Hello, processor","max_new_tokens":20}'
```

The HTTP process holds one model warm. It uses the actual model's tokenizer and `generate()` method; there is no remote inference API. Only `/health` and `/query` exist. The default loopback bind reduces exposure. External deployment requires explicit authentication, TLS termination, and request-rate/budget governance; this module is not a production internet gateway. Never store private prompts or full generated text in a public branch or public CI artifact.

## Evidence and real constraints

| Claim | Level established by code |
|---|---|
| Any-size architectural model identity and weight addressing | Schema is parametric, not hard-coded to GPT-2 or a fixed total parameter count |
| 128-expert sparse mathematical inference | **Locally verified** with actual synthetic tensors and independent PyTorch reference |
| F16/BF16 Safetensors input | BF16 payload successfully ingested and executed in local tests |
| Native E-CPU operator execution | Integration tests written; **hosted E-CPU test pending** |
| Arbitrarily large pretrained inference | **Not yet demonstrated**; needs provisioned model, compatible backend, adequate resources and placement |
| Interactive text response | Supported by the real Transformers backend; no live pretrained session was executed locally in this build |
| Durable neural session across host deaths | **Not yet implemented**; VP-001 journal is a distinct affine processor, not a language-model KV checkpoint |
| Multi-host authenticated tensor paths | Reuse E-CPU transport + IFS TCR mechanisms in follow-up; this new numeric sublayer currently executes at one receiver |

## Reusing all three research repositories

- **E-CPU**: `VirtualLayerRuntime`, `HeadlessOS`, `Hypervisor`, `OperatorSpec`, `SystemSeedEnvelope`, and native operator replay/admission. This implementation does not reimplement E-CPU authority.
- **In-Formation-Space**: TCR-001/002/003 demonstrated parameter-owning neural cut realizations and numerical receipts. This milestone adapts TCR-003's receiver-owned native operator pattern to MoE SwiGLU. The new CI checks out IFS by exact commit and runs its original native-admission regression suite; no TCR code is copied into this repository.
- **Virtual-Ground-Interpreter**: independent Ground, observer and proof obligations remain outside neural execution truth. The cross-repository CI also runs VGI verification, but **this is not yet a numerical equivalence proof of the new sparse operator**. Extending VGI's typed model-topology adapter to Qwen3 MoE is a separate milestone.

## Next meaningful steps

1. Admit and execute **complete GQA + RoPE + RMSNorm + sparse SwiGLU layers**, with actual pinned Qwen3 parameter shards and independent numerical comparisons. Connect the VP-002 typed layer DAG to results, not just readiness.
2. Implement **remote resident tensor shards and authenticated E-CPU actor routing** using existing IFS TCR and E-CPU `ReliableChannel` / `SocketTransport`, then test same-session KV and expert movement among independently hosted receivers.
3. Make a **recoverable inference session** with content-addressed KV pages, tokenizer/model identity, generation ledger, commit fencing and replay after process death. Borrow E-CPU recovery lineage and IFS SQLite route epochs rather than making new authorities.
4. Operate a complete preprovisioned Qwen3 model with the hosted backend as an independent comparison oracle; migrate individual verified operations to E-CPU's native tensor path, measuring accuracy, communication bytes, latency and failures.

The direction is model-size independent **as a contract**, not unlimited computational capacity. Every realized result still requires real authenticated access to the declared tensor data, supported numerical primitives, adequate resources, and a checkable completion receipt.
